## 1. 你需要的两样东西

**一台电脑**（Windows、macOS、Linux 都行）和**网络**。

网络这件事要分清楚，因为它决定了你能不能先离线看效果：

| 你要做的事 | 要不要联网 |
|---|---|
| 把项目下载到电脑上（复制一份） | **要**（从 GitHub 上复制） |
| 看演示效果（`npm run demo`） | **不要**——数据是仓库里自带的 |
| 用内置样本跑一遍完整流程（`npm run collect:offline`） | **不要** |
| 在本机预览网站（`npm start`） | **不要**——它只是一个本地小服务器 |
| 真的去网上采集最新数据（`npm run collect`） | **要**，而且要访问 GitHub 和它放说明文档的域名 |
| 把网站发到网上给别人看 | **要**（托管平台要从网上下载你的代码） |

对 Windows 用户的一句提醒：这本手册里凡是"命令行"三个字，都指那个**用键盘打字、按回车**的黑窗口。
网站上还有一页更细的图文说明——[新手准备页](../public/prepare.html)（在本地预览起来之后，
点页面底部的「新手准备页」就能看到），它把开命令行、装没装 Node、命令粘到哪里讲得更慢一些。

## 2. 怎么打开命令行

命令行就是一个用键盘打字下命令的窗口：没有按钮、没有图标。**你只需要做两件事：粘一行字、按回车。**

在 Windows 上，两种走法任选一种（两种都能用）：

**走法 A：PowerShell**（推荐，新一点的系统都自带）

1. 按键盘左下角的 **Windows 键**（上面有个窗口图案那个）。
2. 直接打字输入 `PowerShell`。
3. 屏幕上会出现「Windows PowerShell」，点它（或者按回车）。

**走法 B：命令提示符（cmd）**

1. 按 Windows 键，输入 `cmd`。
2. 出现「命令提示符」，点它。

macOS 上按 `Command` 加空格，输入 `终端` / `Terminal`，回车。

打开之后你会看到一个深色（或黑色）的窗口，里面有一行字，末尾通常是一个 `>` 号，后面有个光标在闪。
**那个光标就是在等你打字。**

> 看到的东西和上面不一样？没关系。只要你面前有一个窗口、里面有一行字和一个在闪的光标，
> 那就是命令行窗口，可以继续往下做。

**接下来所有命令都是"复制一行、粘进这个窗口、按回车"。** 最常犯的错是把命令粘到了
"按 Windows 键弹出来的搜索框"或者浏览器地址栏里——粘错地方它不会理你。

## 3. 怎么装 Node

这个项目本体只需要 **Node.js 22 或更新的版本**（读作"诺德"）。

### 先看装没装

在刚才那个窗口里，用键盘打上：

```
node -v
```

注意 `node` 和 `-v` 中间有个空格。打完按回车，两种结果：

- 屏幕上冒出一行像 `v24.21.0` 这样的东西 —— **已经装好了**，跳到第 4 节。
- 屏幕上说「不是内部或外部命令」「无法将……识别为 cmdlet」或者类似的英文 —— **还没装**，接着往下看。

### 没装的话

1. 打开浏览器，访问官方网站：<https://nodejs.org/>
2. 页面上有个大大的绿色按钮，写着 **LTS**（长期支持版）。点它下载。
3. 下载下来是一个 `.msi` 安装包，双击它，一路点「下一步 / Next」，最后点「安装 / Install」。
   （Windows 以外的系统下载到的会是别的格式，双击按提示装即可。）
4. 装完**把命令行窗口关掉、再重新打开一次**——这一步很关键：老窗口认不出刚装的工具。
5. 在新窗口里再敲一次 `node -v`，这次应该就能看到版本号了。

看到版本号是 `v22` 以上的就行（`v24`、`v26` 都行）；如果打出来是 `v18` 这类更旧的版本，
去同一个官网下载最新 LTS 覆盖安装一次。

## 4. 怎么把项目跑起来

### 第一步：把项目复制到自己电脑上

在命令行窗口里敲（`clone` 后面那一串地址换成你实际的仓库地址）：

```
git clone https://github.com/<你的账号>/github-hotspot.git
```

如果你是从别人那里拿到的压缩包，把它解压到任意一个文件夹，然后跳过这一步。

> 提示「不认识 git 这个命令」也没关系：去 <https://git-scm.com/downloads> 下载安装，
> 或者直接下载仓库的 ZIP 压缩包解压，效果一样。

### 第二步：进入项目目录

```
cd github-hotspot
```

`cd` 是"进去"的意思。敲完之后，命令行提示符前面通常会多出 `github-hotspot` 这几个字，
说明你已经站在这份代码的门口了。**后面所有命令都必须在这个目录里敲**——
换个目录敲，它会说找不到文件。

### 第三步：先看效果，不联网

```
npm run demo
```

跑完会打印一行地址，像 `http://127.0.0.1:8765/`。**把它复制到浏览器地址栏里打开**，
你就能看到整站了。

- 这一条**不联网、也不用先采集**：用的是仓库里自带的一份演示数据。
- 页面上会明明白白写着「这是演示数据（示例），不是刚采集到的真实数据」。
  也就是说：**它长得就是真的，但内容不是"最近真的在流行什么"。**
- 想停止它：回到命令行窗口，按 `Ctrl` 加 `C`（按住 Ctrl 再按 C）。

看到三个榜都有卡片，就说明你已经跑起来了。

### 第四步：让"你自己的数据"出现在页面上

`npm run demo` 看的是自带样本。要让页面显示**你自己电脑上采集出来的数据**，有两条路：

- **不联网**：`npm run collect:offline`——用内置样本把完整流程跑一遍，产物写进你的数据目录，
  页面上同样会标注"这是演示数据"。
- **联网**：`npm run collect`——真的去网上采最新数据。这一步需要网络，也要等几分钟到十几分钟。

采完之后用这条命令预览，然后刷新浏览器：

```
npm start
```

`npm start` 和 `npm run demo` 的**唯一区别**就是数据从哪来：前者读你采集出来的真实数据，
后者读仓库自带的演示数据。

> 第一次打开 `npm start` 可能会看到「还没有任何榜单数据」——这是**诚实**的，不是坏了：
> 数据目录一开始是空的（它被 git 忽略了，不会被复制下来）。跑一次上面任意一条采集命令，再刷新就好。

## 5. 四条命令分别干什么

这一节把四条命令一条一条说清楚，包括它们会写哪些文件。

### `npm run demo` —— 离线演示数据

- **要不要联网**：不要。
- **它做什么**：把仓库自带的那份演示数据摆好，起一个本地小服务器，把地址打印出来。
- **数据在哪**：只在临时目录 `data/demo/` 里，**不会写进 `public/data/`**。
  这一点是故意的：否则你看完演示数据、再跑 `npm start`，就会把演示数据当成真实榜单看，而页面上没有任何标注——
  那就是在说谎。
- **页面会标注吗**：会。榜单上方写着"这是演示数据（示例）"。
- **适合谁**：第一次拿到这份代码、只想看看它长什么样的人。

### `npm run collect:offline` —— 用内置样本跑一遍完整流程

- **要不要联网**：不要。它**一个网络请求都不发**。
- **它做什么**：走完和真实采集完全一样的流程（挑项目、算分、组榜、落盘、写日报），只是数据来自内置样本，
  而不是从网上抓的。
- **数据在哪**：写进**你自己的数据目录** `public/data/`（还会写一份 `daily/2026-10-11.md` 这样的日报）。
- **页面会标注吗**：会。这一条比 `demo` 更进一步：**写进文件的每一天自己都带着"这是内置样本"这个标记**，
  所以无论用哪种方式打开页面，它都会被标出来。仓库里有一条测试专门盯住这件事。
- **适合谁**：想看清"完整流程会产出什么文件"的人；以及断网时的应急演示。

### `npm run collect` —— 真正联网采集

- **要不要联网**：要。
- **它做什么**：去 GitHub 上把候选项目捞出来、一个一个核实信息、算分、排出三个榜，
  然后把结果写成当天的一份 JSON，再写一份给人看的日报。
- **大概要多久**：几分钟到十几分钟。因为请求是**严格串行**的（一次只发一个），
  失败还会退避重试——不串行的话，几个并发请求就能把 GitHub 打到超时。
- **会写哪些文件**：

  ```text
  public/data/2026-10-11.json        今天完整的三个榜单（网站读的就是它）
  public/data/index.json             有数据的日期列表
  public/data/history/2026-10.json   按月存的归档快照（写着，但目前没有任何代码读它）
  daily/2026-10-11.md                给人看的日报
  daily/2026-10-11.json              同一份日报的 JSON 版
  data/cache.json                    本地缓存，让同一批项目不会被反复问
  ```

- **额度限制（很重要）**：不登录 GitHub 时，接口有每小时次数限制。本项目**自己设了 45 次请求的上限**，
  用完就主动收工，并把这一轮标成"数据不完整"——页面上会出现相应提示，而不是静默地少几条。
  想跑得宽裕一点，可以设置环境变量 `GITHUB_TOKEN`（在 GitHub 的 Settings → Developer settings 里生成一个
  访问令牌），PowerShell 里写成 `$env:GITHUB_TOKEN="你的令牌"`，然后照常跑 `npm run collect`。
- **它需要访问的域名**：`api.github.com`（项目数据）、`github.com`（趋势页面）、
  `raw.githubusercontent.com`（读项目的说明文档，用来判断有没有中文说明）。
  **只有 `api.github.com` 通、后面某一个不通时**，采集通常还是能跑完，只是会缺一部分信息
  （例如中文说明那一项），页面上会照实少标一个徽章，不会编一个出来。
- **它不会自己跑**：数据是你敲命令那一刻采的。仓库里带了一个**可选的**每日定时任务，
  但它**只在 GitHub 上生效**（见下一节）；不启用它的时候，榜单只在你手动采过之后才更新。
  想在自己电脑上定时采，就自己建一个计划任务
  （Windows 的"任务计划程序"、macOS/Linux 的 `cron` 都行），让它定时跑这条命令。

### 想让它每天自己采一次？（可选，只在 GitHub 上生效）

仓库里带着一份现成的工作流：`.github/workflows/daily.yml`。把它放在 GitHub 上并启用之后，
GitHub 会每天 UTC 23:00 替你跑一次 `npm run collect`，并把采集产物提交回仓库。

**它不会在你自己的电脑上生效。** 这四件事要先知道：

1. **要允许 Actions 写入。** 提交采集产物需要写权限。工作流里已经写了
   `permissions: contents: write`；如果仓库或组织把 "Workflow permissions" 设成了只读，
   提交那一步会被拒（报 `Resource not accessible by integration`），
   需要到 Settings → Actions → General → Workflow permissions 改成 "Read and write permissions"。
2. **别人 fork 你的仓库之后，默认不会自动跑。** GitHub 会默认禁用 fork 里的定时任务，
   必须在那个 fork 里手动启用。另外公开仓库连续 60 天没有活动时，GitHub 也会自动停掉它。
3. **额度够用。** 工作流用的是 GitHub 自动提供的 `GITHUB_TOKEN`：core 额度从"未登录的 60 次/小时"
   变成 **1000 次/小时/仓库**，而本项目一轮采集只花 **45 次请求**左右。
4. **随时可以手动跑。** 工作流带了手动触发，GitHub 的 Actions 页面里有一个「Run workflow」按钮。

不想用它就把它删掉——删掉之后一切照旧，只是不再有人替你定时采。
（这两条行为出自 GitHub 官方文档：
[REST API 额度](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) 与
[schedule 事件](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)；
官方也说明定时任务在高峰期可能被推迟。）

### `npm start` —— 本地预览

- **要不要联网**：不要。
- **它做什么**：起一个只提供 `public/` 目录文件的小服务器，打印地址。
  它**没有后台、没有接口、没有数据库**，也不会读写你的数据文件——页面需要的 JSON 由浏览器自己去取。
- **数据在哪**：`public/data/`。
- **端口被占用怎么办**：默认用 8765。PowerShell 里先敲 `$env:PORT="8766"` 再敲 `npm start`；
  cmd 里敲 `set "PORT=8766" && npm start`。
- **停止**：`Ctrl` 加 `C`。

## 6. 怎么把这个站发到网上

可以。整站是**纯静态网页**，任何静态托管都能放。但有两件事必须说清楚，否则你会发上去一个空站点。

**第一件：发布目录是 `public/`。**

`index.html`、`app.js`、`style.css` 和 `data/` 全都住在 `public/` 底下。所以配置托管平台时，
**把发布目录（Output Directory / Publish Directory）填成 `public`**——不是仓库根目录，也不是 `src/`。

**第二件：`public/data/` 被 git 忽略了。**

这意味着：即使你把代码推上去，平台上构建出来的站点里也**没有数据文件**，
打开只会看到"还没有任何榜单数据"。想线上有内容，二选一：

- **让采集产物进仓库**：打开仓库根目录的 `.gitignore`，把里面的 `/data/` 改成只忽略缓存文件
  （`data/cache.json`），然后提交 `public/data/` 里的 JSON。这就是"公开可查的每日数据"的做法，
  也是最省事的：托管平台什么都不用做，直接发就行。
- **让平台在部署时采一次**：把构建命令填成 `npm run collect`，让它在部署时现采。
  这需要平台能联网，并且建议在平台的环境变量里配上 `GITHUB_TOKEN`（否则额度很紧，很可能采不全）。

三家免费方案都能用，选一个：

**GitHub Pages**

1. 把代码推到 GitHub 上的一个仓库。
2. 仓库 Settings → Pages → Source。
3. 本项目要发布的是 `public/`，而 Pages 的"从分支发布"只能选分支根目录或 `/docs`，
   所以更省事的路子是：新建一个 `gh-pages` 分支，把 `public/` 里的文件放到那个分支的根目录，然后发布它。
   （`public/data/` 里的文件已经靠仓库自带的每日工作流进仓库时，Pages 直接发布那个分支就行。）

**Cloudflare Pages**

1. 进 Cloudflare 控制台 → Workers & Pages → Create → Pages → 连接你的 git 仓库。
2. Build command：留空，或者填 `npm run collect`（想在部署时现采就填它）。
3. **Build output directory：`public`**。
4. 保存，它会给你一个 `*.pages.dev` 的地址。

**Vercel**

1. 进 Vercel → Add New → Project → 导入你的 git 仓库。
2. Framework Preset：选 **Other**。
3. Build command：留空，或者填 `npm run collect`。
4. **Output Directory：`public`**。
5. 部署完会给你一个 `*.vercel.app` 的地址。

> 发布之后要记得：**数据不会自己变新**。要么你重新采集、重新发布；要么启用仓库自带的那个
> 每日工作流（只在 GitHub 上生效），让它每天把新的采集产物提交回仓库。

## 7. 三个榜的入选条件和"为什么它会在这里"

三个榜看的都是同一批被捞出来的候选项目，区别在"谁进得来"和"按什么排"。

### 🔥 本周飙升（排 15 个）

- **谁能进**：下面这六条**同时**成立才行，缺一条就不进：
  1. 没有停止维护（作者没说"这个项目我不做了"）；
  2. 有开源许可证（就是明确写着"你可以拿去用、改、再发布"的那份文件）；
  3. 最近 7 天内有更新；
  4. 总收藏人数不少于 200；
  5. 至少有一条我们核实过的安装方式（现成的安装包、一条命令、按官方说明装，或项目自己写着要编译 / 要先用容器跑）；
  6. 不是纯资料清单（那种"我收集了一堆链接"的项目进不了前两个榜）。
- **按什么排**：三轴总分（满分 100）从高到低；同分按项目全名的字母顺序，所以重复跑结果一样。
- **它回答**："最近大家在玩什么。"

### 🌟 新手能玩（排 15 个）

- **谁能进**：和「本周飙升」**同一套门槛**，一个字都不差。
- **按什么排**：只看**新手友好**这一轴（满分 25）从高到低——总分高但装起来麻烦的项目在这里会排到后面。
- **它回答**："哪些是你今晚真的能装上的。"

### 🏆 经典必玩（排 30 个）

- **谁能进**：**不套上面那六条门槛**——总收藏人数够高就进得来。所以里面**可能有已经停止维护的老项目**。
- **按什么排**：总收藏人数从高到低。**不算分**（这一榜的卡片上不会出现三轴分数条）。
- **为什么会有已经停止维护的项目**：因为它的用途是"给刚来的人补课"——很多人早就用过、资料最多、
  最不容易踩坑的那批东西。它不是"最热"，是"最值得先看"。
- **它回答**："如果要先看一个，看哪个。"

## 8. ⭐ 口碑、能不能跑起来：这三轴各占多少分

前两个榜会给项目算分，满分 100 分，由三部分组成：

| 这一轴 | 满分 |
|---|---|
| **热度**（这一周新增了多少收藏） | **45** |
| **口碑**（这个项目靠不靠得住） | **30** |
| **新手友好**（你真的装得上吗） | **25** |

### 热度（满分 45）

看的是**最近 7 天新增的收藏人数**。一周涨到 **3000** 就是满分，涨得越多分越高，超过就封顶。

为什么不用"总收藏人数"：总收藏高的老项目一抓一大把，那样看不出最近大家在玩什么。

那这个"新增了多少"是哪儿来的？我们不猜。按下面这个顺序一级一级试，**试到哪一级有数据就用哪一级**，
并且把用的是哪一级标在页面上：

1. **实测**——我们逐日记录的前后两次差值（两次之间隔 7 天以上）。这是最准的一种。
2. **实测（刚建的项目）**——项目建了 7 天以内，它的总收藏人数本身就是这一周的量。
3. **GitHub 官方数据**——GitHub 自己的趋势页面写着这个数字，我们照抄（这是转述，不是我们量的）。
4. **实测**——当前收藏人数减去 **7 天前**那一天记下的收藏人数（两次记录正好隔 7 天，
   与第一级一样，只是量的是两个点，粒度更粗）。
5. **约 N（估算）**——从项目公开的活动记录里按时间窗口推算出来的，页面上一定带「约」和「估算」。
6. 以上都拿不到：**我们不写数字**，卡片上写"这一周的新增收藏，我们没有查到"。
   **绝不会用 0 冒充"没涨"**——那是我们不知道的事。

### 口碑（满分 30）

| 小项 | 满分 | 到哪儿算满分 |
|---|---|---|
| 有多少人把它拿去改造 | 8 | 占收藏人数的比例到 15% |
| 最近还在更新吗 | 8 | 2 天内有更新满分；7 天内有更新得三分之二；更久不得分 |
| 近 90 天发过新版本吗 | 6 | 发过就满分 |
| 有开源许可证吗 | 4 | 有就满分 |
| 收藏还在增长吗 | 4 | 在涨就满分 |

**没问到的不惩罚**：发版信息与收藏增长这两项"我们没问到"时给一半分，只有明确知道"没有"才记 0 分。
新项目不会因为"还没有历史"而被扣分。

### 新手友好（满分 25）

| 小项 | 满分 | 怎么给 |
|---|---|---|
| 安装方式 | 18 | 按**最容易的一种**算：有现成的 Windows 安装包 18；一条命令就能跑起来 16；要先装好 Python 再装它 14；要先装好 Node、再照说明敲命令 8；只能自己动手编译 6；只能在容器里跑 4；我们没找到能用的安装方式 0 |
| 中文说明 | 7 | 项目说明里中文占到达标线给 4 分；另有中文文件名的说明文件（例如 `README.zh-CN.md`）再给 3 分。只有其它语言的说明时，我们会照实说"有本地化文档（非中文）"，不给你挂中文徽章 |

卡片上那个 **🟢 一键就能玩 / 🟡 要几步 / 🔴 要懂点技术** 只看**安装方式**这一项，
和热度和口碑无关——它说的是"你要动手到什么程度"，不是"这个项目好不好"。

## 9. 常见问题

**问：为什么榜单是空的？**

多半是因为还没采集过。数据目录 `public/data/` 一开始是空的——它被 git 忽略了，克隆下来不会带数据。
先跑一次 `npm run collect:offline`（不联网）或 `npm run collect`（联网），然后刷新页面。
想先看网站长什么样，用 `npm run demo`。

**问：为什么页面上写着"演示数据"？**

因为那份数据确实**不是从网上采来的**。两种情况下会出现这个标注：你用的是 `npm run demo`，
或者你跑的是 `npm run collect:offline`（用内置样本跑完整流程）。这是故意的：样本数据很好看、
也很像真的，如果不标出来，你可能会以为"最近 GitHub 上真的在流行这些"。
想看真实数据，跑 `npm run collect`。

**问：为什么某个项目显示"我们没有查到"？**

因为那个数字我们**确实拿不到**。最常见的是"这一周新增收藏"：GitHub 不公布收藏的历史曲线，
官方那套能用来推算的数据源这几年也在退化。所以我们宁可写"没有查到"，也不用 `0` 冒充"没涨"——
`0` 的意思是"确认没涨"，而"没查到"的意思是"我们不知道"，这是两件不同的事。
同理，页面上带「约」和「估算」的数字是我们推算出来的，不是量出来的。

**问：为什么某个项目没有安装方式？**

因为我们在它自己的说明里**没找到一条能核实的安装方式**。可能它真的没有（比如只是一个资料清单），
也可能是它写了但写法太自由、我们认不出来。这样的项目：
- 进不了「本周飙升」和「新手能玩」（那两条榜要求至少有一条核实过的安装方式）；
- 但可能出现在「🏆 经典必玩」里——那一榜不套门槛，只看总收藏人数。
另外：**找不到不等于不能用**，只是我们不敢替你保证。

**问：`npm run collect` 报了一堆错，或者页面说"这一期数据不完整"？**

先看它说的是哪一种：

- **额度用完**（提示里会出现"额度"）：等一小时再跑，或者配上 `GITHUB_TOKEN` 再跑。
  已有的数据不会被破坏。
- **某个域名连不上**（例如读说明文档的域名超时）：采集通常还是能跑完，只是少一部分信息
  （例如少了中文徽章）。换一个网络环境再试一次通常就好。
- **`raw.githubusercontent.com` 连不上**：这个域名负责读项目的说明文档。它不通时，
  "有没有中文说明"这类结论会缺失——我们不会编，页面上就没有那个徽章。

**问：某个项目只有 macOS / Linux 版，怎么办？**

榜单上会照实写它的安装方式。如果它只提供别的系统的版本，那它就**不是给你这台电脑用的**，
换一个榜上的项目试。我们的"新手友好"分只看它最容易的一种安装方式，不代表它一定支持你的系统。

**问：装错了怎么卸载？**

这个网站自己**没有安装任何东西**，所以没有"卸载这个网站"这回事——不想要了，把项目目录整个删掉就行。
至于你在榜单上挑的那些项目：它们各自有各自的卸载办法（多半在它们的说明文档里）。
拿不准的时候，先别乱删系统目录里的东西，去项目主页提问或者在搜索引擎里查
"某某项目 怎么卸载 我的系统名"。

**问：命令粘进去了，它说"不是内部或外部命令"？**

两种情况：
- 提示的是 `node` 不认识 → Node 还没装，或者装完**没把命令行窗口关掉重开**。回第 3 节。
- 提示的是别的命令不认识 → 少敲了字，或者你现在不在项目目录里。先敲 `cd github-hotspot` 回到项目目录。

**问：网站看不到我的电脑，那它怎么知道我没装 Node？**

它**不知道**。这个网站是纯静态页面，看不到你的电脑，也不会去猜。所有"你装没装什么"都得你自己
在命令行里敲一条命令看结果。

## 10. 已知限制

这几条是**现在真的做不到**的事，不是"以后会补"的客气话：

1. **联网采集这条路没能在开发那台机器上端到端验证过。** 那台机器访问 `raw.githubusercontent.com`
   会超时，所以 `npm run collect` 的完整联网路径是"读过代码 + 有单元测试"，但没有在那里真跑通过。
   不联网的那条路（`npm run collect:offline`）是完整跑通并验证过的。
2. **浏览器里的行为只验证到"显示逻辑"这一层。** 项目把所有"该显示什么"的判断都写在
   `public/render.mjs` 里（不碰浏览器、纯函数，能被 `node --test` 直接断言），所以那些判断是有测试的；
   但开发这个项目的环境里起不了浏览器，**没有人真的用鼠标把整站点过一遍**。
   第一次用的时候建议你自己点一遍：切三个榜、改筛选、点开一张卡片、复制一条命令、换一天。
3. **月度归档文件是一张空头支票。** 每次采集都会写 `public/data/history/YYYY-MM.json`，
   但**目前没有任何代码读它**——它只是留着以后用的档案，现在**不是一个功能**。
   算增长用的是每天那份数据里 7 天前的那一天，跟这个归档文件没有关系。
4. **定时任务只在 GitHub 上，而且没有在真实仓库里跑过。** 仓库里带了一份可选的每日工作流
   （`.github/workflows/daily.yml`），但**它不会在你自己的电脑上跑**；本机没有 GitHub 仓库可挂，
   所以"它在 Actions 里真的跑成了"这件事没人验证过——第一次启用后请到 Actions 页面看一眼。
   另外：**没有安装器，也没有本地探测**。这个网站不会替你检查、安装、修改电脑上的任何东西。
5. **榜单上的项目是别人写的。** 我们只负责"挑出来、说人话"，**没有审计它们的代码**，
   也不保证它们一定装得上、一定好用。要不要装、装什么，你自己拿主意。
6. **数字不是实时的。** 页面上的数字是采集那一刻的，可能已经是几个小时前、甚至几天前采的
   （页面上写着它属于哪一天）。要新的，就重新采一次。
7. **本项目开发环境里跑不了 `npm test`，这不是项目的问题。** 项目自己的测试在普通电脑上
   敲 `npm test` 就能正常通过。只是这个项目**开发时所处的受限环境**不允许 `node --test`
   为每个测试文件派生子进程，那里会报 `spawn EPERM`——那是**环境不允许**，不是测试失败。
   在那种环境里想跑同一批用例，用
   `node --test --test-isolation=none test/*.test.mjs`（不派生子进程，四百多条用例全过）。

## 11. 不做什么

- **不做第 N 个趋势页面搬运工**：只把热门条目抄下来这件事，已经有人做得很好了。我们想做的是
  "挑出来 + 说清楚你能不能装"。
- **不做后端**：整站是纯静态的，没有账号、没有数据库、不收集你的任何信息。
- **不做承诺**：页面上不会说"数据会自己变新"这种话（引它出来，是为了说明为什么不会有这句），
  因为仓库里确实没有对应的机制。
